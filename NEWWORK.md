# New work log

Dated record of what was built during the Meta hackathon. This file should stay aligned with the commit history.

## 2026-10-26

- Initialized Kiln as a new Python 3.12 project. No application code was imported from another product.
- Added the package layout for the gateway, agents, orchestration graph, sandbox, tools, and event log.
- Wired FastAPI, Pydantic models for the spec, task graph, and test report, and a LangGraph pipeline whose nodes do not call models yet.
- Added the model gateway: OpenAI-compatible client for Meta Model API, role routing, retry, token log, and a hard token ceiling.
- Added the Docker sandbox contract: no network, resource caps, no secrets in the container, and a JUnit result parser.
- Meta Model API credits were already requested. The GitHub repo `Uknowme-h/kiln` is still private.
- Added the floor view: a typed SSE event contract (`events/schema.py`), a scripted demo feed (`events/demo.py`), and a no-build-step office UI (`ui/`) served by FastAPI at `/`. Agents sit at desks, envelopes fly on hand-offs, a CI rack shows red/green, and a token meter tracks spend. The demo feed calls no models and writes no files; real events replace it once the LangGraph nodes emit them.
- Rebuilt the UI as a pixel-art office in the style of office-floor agent viewers. Every visual is drawn procedurally in code (`ui/engine.js`, `characters.js`, `props.js`, `scene.js`): a custom cast of seven agent sprites (one per role), desks with PCs, a cork task board, plants, and the CI rack. No image assets are bundled, so nothing is licensed or pre-dates the hackathon. Studied the referenced repo's design system for the palette and the procedural-sprite technique; the character designs, layout, and all code are our own.
- Furnished the office into named zones, all procedural: a meeting corner (conference table with chairs, whiteboard with a scribbled flowchart, easel task board), a wall with windows, a rocket poster, the KILN studio sign, and a wall clock that shows real time; a docs corner (bookshelf, file cabinet, printer table) next to the reporter; a break nook (couch, water cooler, coffee counter, ficus); hanging zone signs and floor decals. Agents sit behind their desks with the PC in front of them.

## 2026-10-27

- Separated the office into real rooms, following the reference repo's approach of wall segments with door gaps: the meeting room is walled with two doorways, cubicle partitions divide the plan desks, a divider with a doorway marks the docs corner, and the break nook sits on warm wood flooring. Regrouped the furniture (break items in a row, bins against walls) so nothing floats.
- Added event-driven station visits: the requirements analyst walks to the whiteboard, the fixer walks to a failing worker's desk when a help message arrives, and the reporter walks to the printer; each walks home when its status goes done. Desks stay home while bodies move. Task assignments pin a color-coded sticky note on the cork board, and notes get a green check when the run goes green. The demo feed now emits `done` for the planning roles so the floor settles at the end.
- Added `scripts/cdp_shot.py`, a dev-only helper that screenshots the floor mid-run over the Chrome DevTools Protocol (used to verify the animations; not part of the app).
- Replaced the ad-hoc walks with a logical office choreography. Every movement maps to a real office action: a run starts with a kickoff meeting (analyst + PM walk to the conference table), the analyst drafts the spec at the meeting-room whiteboard, the PM takes the spec back to his desk to plan, assigned tasks pin on the sprint board and each worker walks over to collect their card (standup), the failing dev's desk gets a pair-debugging visit from the fixer, and the reporter walks to the printer. The run ends with a celebrate hop from everyone. The meeting room was re-laid (whiteboard left, table right) so routes never cross furniture, and desks glow only while their owner is seated and working.
- Demo runs can no longer interleave: a new `POST /demo/run` cancels the run still playing.
- Probed Muse Spark 1.3 once each for streaming, a tool call, and structured JSON (`scripts/probe_spark.py`). All three worked. Streaming returned `ready`. The `record_note` tool was called with `{"note":"ready"}` (548 prompt tokens, 94 completion tokens). Strict `json_schema` output validated as a `TaskGraph` with two tasks and non-overlapping paths (62 prompt tokens, 368 completion tokens). `tool_choice` was left on `auto`, which is the only value this API accepts.

## 2026-10-28

- Added `docs/client-console.md`: the user-facing design (idea brief, mid-run notes drained by the planner at phase boundaries, workspace handoff with zip download) mapped onto the remaining build schedule. Design only, no code changes yet.
- Studied how `anomalyco/opencode` and `morluto/rea` structure their agents and wrote `docs/agent-patterns.md`: eight refinements adopted (declarative role definitions, status-report loop caps, worker sources/conclusions/gaps contract, untrusted-user-text rule, trial-rigor eval harness, evidence-ledger reporting), with each mapped to a day in the build schedule. No upstream code copied; patterns only.
- Researched Meta's Muse Code (release posts, docs, cookbooks, press) and wrote `docs/muse-code-comparison.md`: how its subagent fan-out, workflows, event log, observers, and goal tracking work; an honest feature comparison; and three adoptions for this week — name-the-exact-oracle acceptance criteria (today), a no-progress step probe for the fixer loop (Oct 30), and a persisted per-run `events.jsonl` that doubles as the cached fallback demo (Nov 1–2).
- Architecture decision: agents work on the **user's own machine**, not the server. A browser cannot write local files or run Docker (platform guarantee), so `docs/local-companion.md` adds a small local companion process (`uvx kiln-companion connect CODE --dir .`) that the server drives over one outbound WebSocket — scoped file tools plus the Docker test runner, supporting an existing repo, an empty repo, or no repo. The Meta API key stays server-side; the zip-download Handoff is dropped (files are already home); `docs/client-console.md` updated to match.
- Wired the requirements analyst for real (`agents/requirements.py`): idea → `Spec` via Muse Spark strict `json_schema`, validated on every run, one retry with the validation error shown, then a counted failure. The prompt (`agents/prompts/requirements.txt`) wraps the idea and user notes as untrusted quoted content and demands oracle-named acceptance criteria — every criterion names the exact test that proves it. `AcceptanceCriterion.oracle` is now a required field.
- Added `agents/definitions.py` (declarative per-role tools, write prefixes, caps) and `schemas/jsonschema.py` (strict-mode conversion: `additionalProperties: false` and full `required` on every object — the API rejects anything less, found via live smoke). The gateway now forwards `response_format`. `RunState` gained `user_notes` and `spec`; the pipeline's requirements node calls the analyst when one is provided and stays stubbed otherwise.
- The floor contract gained a `note_added` event; the demo feed rehearses a mid-run client note ("tasks need a due-date field") and the planner's re-plan reply; the UI logs it (full envelope animation comes with the console).
- Live smoke (`scripts/smoke_requirements.py`): "a to-do app with user accounts and a REST API" → valid spec on the first attempt — 4 stories, 11 criteria with oracles, Flask + SQLite + JWT in 4 files, scope-tight assumptions — for 3,649 tokens. 47 tests pass, ruff clean.
- Built the client console against the demo feed, per `docs/client-console.md`: the **Brief** (idle overlay with idea textarea, the three golden prompts as one-click chips, Enter-to-submit, floor dimmed behind), the **Note Dock** (bottom composer during runs), and the **Handoff** (results card: tests, tokens, the brief, "Brief the team again"). `ui/app.js` is now a small state machine (idle → running → finished).
- The client envelope moment: `scene.clientNote()` flies an envelope in from off-screen to the cork board and pins a lemon sticky; `note_added` log lines get a distinct "you" style. Backend: `/demo/run` accepts an optional `{idea}` body, and `/demo/note` echoes a client note onto the floor — both stand in for `/runs` and `/runs/{id}/notes` until real runs exist (the JS handlers are marked for the switch).
- Verified all three console states visually with headless Chrome + `scripts/cdp_shot.py`: Brief overlay, mid-run dock with a user note landing in the log, and the green Handoff card. 49 tests pass, ruff clean.
- Built the local companion and the run relay per `docs/local-companion.md`. Server side: `POST /runs` (returns a 6-char no-look-alike pair code and the exact connect command), `GET /runs/{id}`, `POST /runs/{id}/notes` (the planner mailbox), a `/runs/{id}/probe` dev aid, and the `/companion/ws` WebSocket endpoint. The registry (`companion/registry.py`) tracks runs and connections, relays `call_tool` with per-call futures and timeouts, resolves results thread-safely across loops (`call_soon_threadsafe`), fails in-flight calls on disconnect, and lets a disconnected companion re-claim its code.
- Companion side (`kiln-companion connect CODE --dir .` / `--new name`): checks Docker is present, scopes every file op through `safe_relative_path` plus a re-resolve under the workspace root (`companion/executor.py`), and runs the Docker test sandbox unchanged. Shell commands never execute on the host. Wire protocol is hello / tool_call / tool_result / ping-pong (`companion/protocol.py`).
- Found a real TestClient limit: a held-open websocket does not interleave with a concurrent request from a second client, so the full duplex relay is covered by `scripts/smoke_companion.py` against real uvicorn instead of the unit suite. Smoke passed: real CLI paired, wrote and read a file in a temp workspace, and refused a `../escape.txt` write. 71 tests pass, ruff clean.
- Wired the PM planner (`agents/planner.py`): spec → `TaskGraph` via Muse Spark strict json_schema, same validate-retry-once-fail discipline as the analyst. The prompt (`agents/prompts/planner.txt`) plans from the acceptance criteria and file plan, caps at six tasks, forbids overlapping ownership and test-file ownership, and folds client notes into scope without letting them rewrite the spec. The pipeline now takes `analyst`/`planner` callables and stays stubbed for the rest. Live smoke: the to-do spec planned into 3 tasks (foundation → API, UI independent) with clean non-overlapping owned paths — 9,331 tokens total for spec + plan. 79 tests pass, ruff clean.
- Integrated the console with the real run API: the Brief now calls `POST /runs` and shows the **pairing panel** (big pair code, the connect command with a copy button, "waiting for your machine…"), polling `GET /runs/{id}` until the companion claims it. On attach the panel dismisses, the Note Dock goes live against `POST /runs/{id}/notes` (the real planner mailbox, with the floor echo), and a disconnect flips the panel back with "re-run the same command to resume". The demo rehearsal still works from the header button and replaces any waiting run. Verified on camera with headless Chrome + a real companion process: pairing → connected → note queued → reconnect after a drop. 79 tests pass, ruff clean.
- Fixed two first-use papercuts: the Brief flow now rejects stale-server replies that lack a pair code with a clear "restart uvicorn" log line instead of rendering "undefined", and the connect command is no longer bare `uvx kiln-companion` (the package is not on PyPI) — it comes from a new `COMPANION_COMMAND_PREFIX` setting, defaulting to `uvx --from git+https://github.com/Uknowme-h/kiln kiln-companion`.
